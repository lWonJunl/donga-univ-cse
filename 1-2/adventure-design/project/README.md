# 📅 약속ZIP

여러 사람의 가능한 시간과 선호도를 비교해 약속 시간을 찾는 C 콘솔 프로그램입니다. 참가자별 주간 시간표를 바탕으로 조건에 맞는 시간을 검색하고, 참석 인원과 선호도가 높은 시간대를 추천합니다.

## 📂 Overview

여러 명이 약속을 잡을 때는 각자의 가능한 시간을 확인하고 공통으로 만날 수 있는 시간을 비교해야 합니다. 약속ZIP은 참가자의 시간표를 한 곳에서 관리하고, 약속에 필요한 시간과 최소 참석 인원을 기준으로 가능한 후보를 찾습니다.

모든 참가자가 참석할 수 있는 시간을 찾을 수도 있고, 최소 참석 인원을 조정해 일부 참가자가 가능한 시간도 검색할 수 있습니다. 검색한 후보는 참석 인원과 선호도를 기준으로 정렬합니다.

## 🎯 Project Goals

- 참가자별 참석 가능 시간과 선호도를 기록합니다.
- 모든 참가자 또는 최소 인원 이상이 함께할 수 있는 시간을 검색합니다.
- 참석 인원과 선호도를 비교해 약속 시간 선택을 돕습니다.

<br>

## ✨ Key Features

- **참가자 관리**: 참가자를 등록·조회·검색·삭제합니다. 최대 8명까지 등록할 수 있으며, 삭제된 배열 공간은 재사용합니다.
- **시간표 관리**: 월요일부터 일요일까지 오전 9시~오후 9시를 한 시간 단위로 관리합니다. 각 시간대의 참석 가능 여부와 선호도를 입력하고 수정·조회할 수 있습니다.
- **공통 가능 시간 검색**: 약속 소요 시간(1~12시간)과 최소 참석 인원을 입력해 조건을 만족하는 시간대를 찾습니다. 약속의 모든 시간대에 참석할 수 있는 참가자만 포함합니다.
- **추천과 상세 조회**: 검색 결과를 참석 인원, 평균 선호도, 이른 요일과 시간 순으로 정렬해 최대 3개를 추천합니다. 각 후보의 참석 인원·비율과 참석 가능·불가능 명단을 확인할 수 있습니다.

<br>

## 🚀 Quick Start

C11을 지원하는 컴파일러가 필요합니다. 프로젝트 폴더에서 GCC를 사용하는 Windows PowerShell 예시는 다음과 같습니다.

```powershell
gcc -std=c11 -Wall -Wextra -Wpedantic main.c -o main.exe
.\main.exe
```

## 🧭 Usage

1. **1번 참가자 등록**에서 이름을 입력합니다. 이름은 공백 없이 최대 63바이트이며 중복할 수 없습니다.
2. **5번 가능 시간 및 선호도 입력**에서 참가자, 요일, 시작 시간과 참석 가능 여부를 선택합니다. 가능한 시간에는 1.0~5.0점의 선호도를 0.1점 단위로 입력합니다.
3. **6번 시간표 조회 및 수정**에서 입력한 주간 시간표를 확인하거나 시간대별 값을 변경합니다.
4. **7번 공통 가능 시간 검색**에서 약속 소요 시간 1~12시간과 최소 참석 인원을 입력합니다.
5. **8번 최적 약속 시간 추천**에서 상위 후보를 확인하고, **9번 추천 결과 상세 조회**에서 순위를 입력합니다.

참가자 목록의 번호는 화면에 표시되는 순번입니다. 참가자 고유 ID는 이름 검색 결과에서 확인할 수 있습니다.

### 참가자 관리

- 이름은 한 줄에 공백 없이 입력합니다. 이름의 최대 길이는 63바이트이며, 등록된 이름을 중복해서 사용할 수 없습니다.
- 목록에는 현재 등록된 참가자만 표시하며, 등록 ID가 작은 순서대로 목록 번호를 1부터 붙입니다.
- 삭제할 이름을 입력하고 `Y`를 선택하면 해당 참가자의 시간표도 초기화합니다. `N`을 선택하면 삭제를 취소합니다.
- 삭제된 배열 칸은 새 참가자에게 다시 사용합니다. 새 참가자는 새 ID를 받으므로 화면의 목록 번호와 ID는 서로 다를 수 있습니다.

예를 들어 ID 1인 참가자를 삭제한 뒤 새 참가자를 등록하면, 비워진 배열 칸을 사용하면서도 다음 ID를 부여합니다.

### 시간표 관리

시간표 입력과 수정은 참가자 한 명의 **한 시간대**를 처리합니다. 요일은 월요일부터 일요일까지 1~7로 입력하고 시작 시간은 9~20으로 입력합니다. 참석 가능을 선택한 경우 선호도를 1.0~5.0 사이에서 소수 첫째 자리까지 입력합니다.

6번 메뉴에서 조회를 선택하면 한 주의 84개 시간대를 요일별로 확인할 수 있습니다. 수정은 이름과 시간대를 다시 선택해 참석 여부와 선호도를 바꿉니다. 불가능으로 설정한 시간에는 선호도를 입력하지 않으며, 설정하지 않은 시간도 불가능으로 표시합니다.

### 메뉴 안내

| 번호 | 메뉴 | 사용 방법 |
| --- | --- | --- |
| 1 | 참가자 등록 | 이름을 입력해 참가자를 추가합니다. |
| 2 | 참가자 목록 조회 | 등록된 참가자를 ID 순서로 확인합니다. |
| 3 | 참가자 검색 | 이름으로 검색해 참가자 ID와 등록 상태를 확인합니다. |
| 4 | 참가자 삭제 | 이름을 찾은 뒤 `Y` 또는 `N`으로 삭제 여부를 선택합니다. |
| 5 | 가능 시간 및 선호도 입력 | 참가자와 요일·시작 시간을 선택해 한 시간대의 값을 저장합니다. |
| 6 | 시간표 조회 및 수정 | 참가자별 주간 시간표를 보거나 선택한 시간대를 수정합니다. |
| 7 | 공통 가능 시간 검색 | 소요 시간과 최소 참석 인원을 기준으로 후보를 찾습니다. |
| 8 | 최적 약속 시간 추천 | 마지막 검색 결과에서 상위 3개까지 확인합니다. |
| 9 | 추천 결과 상세 조회 | 추천 순위를 입력해 참석자 명단과 점수를 확인합니다. |
| 0 | 종료 | 프로그램을 종료합니다. |

### 시간표 입력 예시

참가자 민수가 등록되어 있을 때, 월요일 14:00~15:00에 참석 가능하고 선호도가 4.5점인 경우입니다.

```text
참가자 이름 > 민수
요일 (1: 월 ~ 7: 일) > 1
시작 시간 (9~20시) > 14
참석 가능 여부 (1: 가능, 0: 불가능) > 1
선호도 (1.0~5.0) > 4.5
월요일 14:00~15:00 시간표를 저장했습니다.
```

참석 가능 여부에 `0`을 입력하면 선호도를 입력하지 않습니다. 잘못된 값을 입력하면 오류 메시지를 출력하고 메뉴로 돌아갑니다.

### 검색과 추천 예시

아래는 참가자 4명 중 3명 이상이 2시간 연속 참석할 수 있는 시간을 검색하는 예시입니다. 시간과 인원은 입력한 시간표에 따라 달라집니다.

```text
약속 소요 시간 (1~12시간) > 2
최소 참석 인원 (1~4명) > 3
=== 검색 결과 ===
월요일 14:00~16:00  참석 가능: 3명
```

검색 결과가 있으면 8번 메뉴에서 추천 순위를 확인하고, 9번 메뉴에서 확인할 순위를 입력합니다.

예를 들어 2시간 약속에서 민수가 14:00~15:00에만 가능하고 지수가 14:00~16:00 두 시간 모두 가능하다면, 해당 후보의 참석 가능 인원에는 지수만 포함됩니다. 이 기준은 3시간 이상 약속에도 동일하게 적용됩니다. 조건에 맞는 시간이 없으면 프로그램이 결과가 없다고 안내합니다.

<br>

## ⚙️ Recommendation

검색된 각 후보의 참석 가능 인원과 평균 선호도를 계산한 뒤 다음 순서로 비교합니다.

1. 참석 가능한 인원이 많은 시간
2. 참석 인원이 같으면 평균 선호도가 높은 시간
3. 인원과 선호도가 같으면 더 이른 요일과 시작 시간

참석 가능 여부는 약속의 전체 소요 시간으로 판단합니다. 예를 들어 14:00~15:00만 가능한 참가자는 14:00~16:00의 2시간 약속 인원에 포함되지 않습니다. 평균 선호도도 해당 약속에 참석할 수 있는 참가자만 대상으로 계산합니다.

## 🔗 Program Flow

```text
프로그램 시작 → 메뉴 선택
                  │
                  ├─ 1~4  참가자 등록·목록·검색·삭제
                  │         └─ 등록·삭제 시 이전 검색 결과 무효화
                  │
                  ├─ 5~6  시간표 입력·조회·수정
                  │         └─ 입력·수정 시 이전 검색 결과 무효화
                  │
                  ├─ 7    약속 길이와 최소 참석 인원 입력
                  │         → 각 시간대의 참석 가능 여부 확인
                  │         → 조건에 맞는 후보 저장 및 정렬
                  │
                  ├─ 8    검색 결과 중 상위 3개 추천
                  ├─ 9    추천 시간의 참석자와 선호도 상세 조회
                  └─ 0    종료
```

[파이프라인과 코드 보기](pipeline.html)에서 각 메뉴의 함수와 연결된 코드를 살펴볼 수 있습니다. 

### 공통 시간 검색의 처리 순서

```text
search_times() · 약속 길이와 최소 참석 인원 입력
    ↓
요일과 시작 시간을 차례로 확인
    ↓
is_available() · 참가자별로 약속 시간 전체에 참석할 수 있는지 확인
    ↓
최소 참석 인원을 만족하는 후보의 시간과 참석자 저장
    ↓
calculate_preference() · 참석자의 평균 선호도 계산
    ↓
sort_results() · 참석 인원 → 평균 선호도 순으로 정렬
    ↓
print_recommendations() · 상위 후보 출력
    ↓
print_result_details() · 선택한 후보의 참석자와 점수 조회
```

등록·삭제와 시간표 입력·수정이 성공하면 `invalidate_results()`가 이전 검색 결과를 무효화합니다. 이후 추천을 보려면 7번 메뉴에서 다시 검색해야 합니다.

참가자나 시간표를 변경하면 다시 검색해 추천 결과를 갱신합니다.

검색 결과는 프로그램이 실행되는 동안 저장됩니다. 8번에서는 후보가 3개보다 적으면 있는 후보만 표시하고, 9번에서는 표시된 순위의 시간·참석률·평균 선호도와 참석 가능 및 불가능 명단을 확인합니다. 후보 시간이 서로 겹칠 수도 있습니다.

7번에서 잘못된 검색 조건을 입력하면 새 검색을 시작하지 않고 메뉴로 돌아갑니다. 이때 이전 검색 결과는 유지됩니다.

## 🛠️ Code Structure

| 구분 | 구조체·함수 | 역할 |
| --- | --- | --- |
| 참가자 정보 | `participant` | ID, 이름, 등록 상태와 요일·시간별 가능 여부 및 선호도 저장 |
| 검색 조건 | `meeting_conditions` | 약속 소요 시간과 최소 참석 인원 저장 |
| 검색 후보 | `result` | 후보 시간, 참석 여부, 인원·비율과 선호도 저장 |
| 참가자 관리 | `register_participant`, `list_participants`, `find_participant`, `delete_participant` | 등록·목록·검색·삭제 |
| 시간표 | `input_schedule`, `update_schedule`, `print_schedule` | 시간대 입력·수정·조회 |
| 검색 | `search_times`, `is_available` | 조건에 맞는 후보와 연속 참석 여부 확인 |
| 추천 | `calculate_preference`, `sort_results`, `print_recommendations`, `print_result_details` | 선호도 계산, 후보 정렬과 결과 출력 |
| 결과 관리 | `invalidate_results` | 참가자 또는 시간표 변경 후 이전 결과 무효화 |

### 데이터 저장 방식

`participant` 배열은 최대 8명의 이름, ID, 등록 상태와 시간표를 보관합니다. 시간표는 요일과 시간대에 해당하는 2차원 배열로 저장합니다. 입력한 요일 1~7은 배열의 0~6에, 시작 시간 9~20은 배열의 0~11에 대응합니다.

`result` 구조체는 참석 인원을 `int`, 참가자별 참석 여부를 `char` 배열, 참석률을 `float`로 저장합니다. 참석 여부는 참가자 배열의 같은 위치에 대응하며 가능하면 `'Y'`, 불가능하면 `'N'`으로 저장합니다.

| 자료형 | 구조체 구성 요소 | 용도 |
| --- | --- | --- |
| `int` | `attendee_count` | 약속 시간에 참석할 수 있는 인원 |
| `char` 배열 | `attending` | 참가자별 참석 가능 여부 (`'Y'` 또는 `'N'`) |
| `float` | `attendance_rate` | 전체 참가자 중 참석 가능한 인원의 비율 |

이 세 구성 요소는 모두 `result` 구조체에 들어 있습니다. 이 밖에도 요일, 시작·종료 시간, 평균 선호도 등을 함께 저장합니다.

`used_slot_count`는 한 번이라도 사용한 배열 범위이고, `deleted_participant_count`는 그 범위 안에서 비어 있는 칸 수입니다. 현재 참가자 수는 두 값의 차이로 구합니다. 삭제된 칸을 재사용할 때는 해당 칸을 초기화하여 이전 참가자의 시간표가 남지 않도록 합니다.

개발 과정에서는 삭제된 참가자의 배열 칸을 비워 두고 다음 등록에서 재사용하도록 했습니다. 이렇게 하면 배열의 위치를 유지할 수 있지만, 재사용 전에 시간표와 선호도를 초기화해야 이전 정보가 남지 않습니다. 입력은 한 줄씩 읽고 숫자 범위를 검사해 잘못된 입력이 다음 메뉴 입력에 섞이지 않도록 했습니다. 여러 시간 약속은 시작 시간만 확인하지 않고 전체 시간대에 같은 참가자가 참석 가능한지 검사합니다.

선호도는 4.5점을 정수 45로 저장합니다. 검색 시에는 참석 가능한 참가자의 점수를 합산하고 약속 시간 수와 참석 인원으로 나눠 평균을 구합니다. 후보는 참석 인원과 평균 선호도 순으로 정렬하며, 두 값이 같으면 먼저 검색된 이른 요일과 시간이 앞에 남습니다.

입력은 한 줄씩 읽어 이름 길이와 숫자 범위를 검사합니다. 시간표나 검색 조건이 잘못되면 오류를 안내하고 메뉴로 돌아갑니다. 참가자가 없거나 검색 결과가 없을 때도 안내 메시지를 출력합니다.

## 🔧 개선할 부분

다음은 현재 구현의 제한과 앞으로 고려할 수 있는 기능입니다.

- **상수 변경**: `START_HOUR`, `END_HOUR`는 같은 날 안의 시작·종료 시간으로 변경할 수 있습니다. `DAYS_PER_WEEK`는 요일 이름 배열과 함께, `NAME_LEN`은 안내 문구와 함께, `INPUT_LEN`은 입력 형식과 함께 수정해야 합니다. `PREFERENCE_SCALE`을 바꾸려면 소수 입력 처리도 수정해야 합니다.
- **시간표 입력 편의성**: 현재는 한 시간대씩 입력합니다. 시작 시간과 종료 시간을 지정해 여러 칸을 한 번에 입력하는 방식을 고려할 수 있습니다.
- **시간표 조회 방식**: 현재는 전체 84칸을 출력합니다. 가능한 시간만 따로 조회하는 선택지를 추가할 수 있습니다.
- **요일 선택 검색**: 현재는 월요일부터 일요일까지 모두 검색합니다. 특정 요일만 검색하는 기능을 추가할 수 있습니다.
- **입력 오류 처리**: 잘못된 요일이나 선호도를 입력하면 메뉴로 돌아가므로 참가자 이름부터 다시 입력해야 합니다. 잘못된 항목만 다시 입력받으면 편리합니다.
- **시간 단위 확장**: 현재는 9시부터 21시까지 한 시간 단위로만 입력하고 검색합니다. 30분 단위나 다른 시간 범위도 다룰 수 있도록 확장할 수 있습니다.
- **미입력 시간 구분**: 현재는 입력하지 않은 시간과 참석 불가능으로 설정한 시간을 모두 불가능으로 취급합니다. 두 상태를 구분하면 시간표 입력이 끝났는지 확인하기 쉽습니다.
- **추천 결과 다양화**: 현재는 시간이 겹치는 후보도 각각 추천합니다. 겹치는 후보를 묶거나 간격을 두고 보여주는 방식을 고려할 수 있습니다.
- **입력 데이터 보관**: 현재는 프로그램을 종료하면 입력한 데이터가 사라집니다. 다음 실행에서도 사용하려면 저장과 불러오기 기능이 필요합니다.

<br>

## 📌 Notes

- 설정하지 않은 시간대는 참석 불가능으로 처리합니다.
- 시작 시간은 오전 9시부터 오후 8시까지이며, 약속은 오후 9시까지 끝나야 합니다.
- 여러 시간 약속의 선호도는 각 참가자의 약속 시간대별 점수를 평균한 뒤 참석 가능한 참가자들의 평균을 계산합니다.
- 참가자 등록·삭제 또는 시간표 입력·수정이 성공하면 이전 검색 결과는 무효화됩니다. 추천과 상세 결과를 다시 보려면 7번에서 검색해야 합니다.
- 입력한 참가자와 시간표는 실행 중에만 유지되며 프로그램을 종료하면 저장되지 않습니다.
