# 약속ZIP 프로젝트 계획 및 설계서

### 과제 조건과 프로그램 구성

여러 사람이 약속 시간을 정하는 상황을 구조체로 나타낸다. 참가자를 등록하고 각자의 시간표를 입력한 뒤, 함께 만날 수 있는 시간을 찾아 추천한다.

| 과제 조건 | 프로그램 적용 내용 |
|---|---|
| `int` | 참가자 구조체의 고유 번호와 등록 상태, 결과 구조체의 참석 인원 |
| `char` | 참가자 구조체의 이름 배열, 결과 구조체의 참석 여부 배열 |
| `float` | 결과 구조체의 참석률 |
| 구성 요소 3개 이상 | 참가자 구조체에 ID, 등록 상태, 이름, 시간표, 선호도 등 포함 |
| 기능 3개 이상 | 참가자 등록·검색·삭제, 시간표 입력·수정·조회, 결과 정렬·추천 등 |

결과 구조체에는 참석 인원(`int`), 참석 여부(`char`), 참석률(`float`)이 함께 들어간다.

## 1. 프로젝트 개요

### 1.1 프로젝트명
약속ZIP — 다인원 약속 일정 자동 조율 프로그램

### 1.2 개발 목적
친구들과 약속을 잡을 때 각자 가능한 시간이 달라서 시간을 정하기 어려운 경우가 있다. 일일이 시간을 비교하는 대신 참가자들의 시간표를 입력해 함께 만날 수 있는 시간을 찾고 싶었다.

참가자마다 가능한 시간과 선호도를 입력하고, 약속에 필요한 시간과 최소 참석 인원을 정한다. 조건에 맞는 시간 중 참석할 수 있는 사람이 많고 선호도가 높은 시간을 추천한다.

### 1.3 개발 환경
- 개발 언어: C 언어
- 실행 환경: 콘솔 기반 프로그램
- 주요 기술: 구조체, 배열, 포인터, 문자열 처리, 반복문, 조건문, 사용자 정의 함수
- 데이터 관리: 실행 중 메모리에 저장
- 외부 라이브러리 및 데이터베이스: 사용하지 않음

## 2. 프로그램 기본 설정 (매크로 상수 설정) 

| 항목 | 설정 |
|---|---|
| 최대 참가자 수 | 8명 |
| 지원 요일 | 월요일~일요일 |
| 지원 시간 | 오전 9시~오후 9시 |
| 시간 단위 | 1시간 |
| 약속 소요 시간 | 1~12시간 |
| 선호도 점수 | 1.0~5.0점 (0.1점 단위) |
| 최소 참석 인원 | 사용자가 설정 |
| 추천 결과 | 최대 3개 |

월요일부터 일요일까지 하루에 12개 시간대를 관리하므로, 참가자 한 명당 총 84개 시간대를 저장한다.

실제 날짜 대신 요일을 기준으로 시간표를 관리한다. 예를 들어 특정 날짜를 고르지 않고 월요일의 가능한 시간을 입력한다.

## 3. 주요 기능 설계

### 기능 1. 참가자 등록 및 관리

약속에 참여할 사람들의 정보를 등록하고 관리한다.

**세부 기능**
1. 참가자 이름을 입력하여 등록한다.
2. 등록된 전체 참가자 목록을 조회한다.
3. 참가자 이름을 이용하여 특정 참가자를 검색한다.
4. 등록된 참가자를 삭제할 수 있다.
5. 이름이 중복되거나 최대 인원을 초과하면 등록을 제한한다.

참가자를 삭제하면 시간표와 선호도도 함께 초기화한다. 비워진 배열 칸에는 새 참가자를 등록할 수 있고, 이때 ID는 새로 부여한다. 이름은 공백 없이 최대 63바이트로 입력한다.

### 기능 2. 참가자별 가능 시간 등록

각 참가자가 약속에 참석할 수 있는 요일과 시간을 입력한다.

**세부 기능**
1. 등록된 참가자 중 한 명을 선택한다.
2. 요일과 시간대를 선택한다.
3. 해당 시간의 참석 가능 여부를 설정한다.
4. 참석 가능한 시간에는 선호도를 1.0~5.0점 사이에서 0.1점 단위로 입력한다.
5. 이전에 입력한 가능 시간과 선호도를 수정할 수 있다.
6. 참가자의 주간 가능 시간표를 조회할 수 있다.

한 번에 한 시간대씩 입력하거나 수정한다. 설정하지 않은 시간은 참석 불가능으로 처리하며, 참석 불가능한 시간의 선호도는 계산에 사용하지 않는다.

### 기능 3. 공통 가능 시간 검색

등록된 참가자의 시간표를 비교하여 설정한 최소 인원 이상이 참석할 수 있는 시간을 찾는다.

**세부 기능**
1. 요일별로 모든 시간대를 검사한다.
2. 각 시간대에 참석 가능한 인원수를 계산한다.
3. 최소 참석 인원을 전체 참가자 수로 정하면 모두 참석할 수 있는 시간을 검색한다.
4. 최소 참석 인원을 줄이면 일부 참가자만 참석 가능한 시간도 검색할 수 있다.
5. 검색된 시간과 참석 가능 인원을 출력한다.

예를 들어 참가자가 5명이고 최소 참석 인원을 4명으로 설정했다면, 4명 이상이 참석할 수 있는 시간대만 결과에 포함한다.

### 기능 4. 약속 소요 시간에 따른 연속 시간 검색

약속에 필요한 시간에 따라 1~12시간 연속 참석할 수 있는 시간대를 검색한다.

**세부 기능**
1. 사용자가 약속 소요 시간을 선택한다.
2. 선택한 시간 동안 연속되는 시간대를 검사한다.
3. 각 시간대에 모두 참석할 수 있는 사람을 계산한다.
4. 약속 시간이 운영 범위인 오후 9시를 넘지 않도록 제한한다.
5. 연속 참석 조건을 만족하는 후보만 출력한다.

예를 들어 오후 2시부터 3시까지는 참석 가능하지만 3시부터 4시까지는 참석 불가능한 사람은 2시간 약속에 참석할 수 없는 것으로 판단한다.

### 기능 5. 최적 약속 시간 자동 추천

검색된 시간대 중 가장 적합한 약속 시간을 자동으로 선정한다.

**추천 기준**
1. 참석 가능한 인원수가 많을수록 우선한다.
2. 참석 인원이 같다면 평균 선호도가 높은 시간을 우선한다.
3. 참석 인원과 평균 선호도가 같다면 더 이른 요일과 시간대를 우선한다.

평균 선호도는 해당 약속에 참석할 수 있는 참가자들의 선호도만 사용하여 계산한다.

약속이 여러 시간인 경우에는 참석 가능한 참가자들의 각 시간대 선호도를 모두 더한 뒤 평균을 구한다.

**추천 결과**
- 1순위: 가장 적합한 약속 시간
- 2순위: 차선의 약속 시간
- 3순위: 세 번째 약속 시간

조건을 만족하는 후보가 3개 미만이면 실제 존재하는 후보만 출력한다.

### 기능 6. 추천 결과 상세 분석

사용자가 추천 결과를 이해할 수 있도록 각 후보의 상세 정보를 제공한다.

**출력 정보**
- 추천 순위
- 추천 요일 및 시작·종료 시간
- 전체 참가자 수
- 참석 가능한 참가자 수
- 참석률
- 평균 선호도
- 참석 가능한 참가자 명단
- 참석할 수 없는 참가자 명단

추천된 시간에 누가 참석할 수 있는지와 평균 선호도를 함께 확인할 수 있다.

## 4. 구조체 및 데이터 설계

### 4.1 참가자 정보 구조체

참가자 한 명의 정보를 하나로 묶어 관리한다.

| 데이터 | 자료형 | 설명 |
|---|---|---|
| 참가자 번호 | 정수형 | 참가자를 구분하는 고유 번호 |
| 참가자 이름 | 문자형 배열 | 이름 저장 |
| 등록 상태 | 정수형 | 현재 등록 여부 구분 |
| 참석 가능 시간표 | 정수형 2차원 배열 | 요일·시간대별 참석 가능 여부 |
| 시간대별 선호도 | 정수형 2차원 배열 | 4.5점은 45로 저장 |

참석 가능 여부는 1과 0으로 구분한다.

- 1: 참석 가능
- 0: 참석 불가능

참가자별 구조체를 배열로 관리하여 최대 8명의 정보를 저장한다. 이름을 기준으로 검색하고, 포인터를 이용해 함수에서 참가자 정보를 수정할 수 있도록 설계한다.

### 4.2 약속 조건 구조체

사용자가 선택한 약속 검색 조건을 저장한다.

| 데이터 | 자료형 | 설명 |
|---|---|---|
| 약속 소요 시간 | 정수형 | 1~12시간 |
| 최소 참석 인원 | 정수형 | 검색에 필요한 최소 인원 |

검색은 월요일부터 일요일까지 전체 요일을 대상으로 한다.

### 4.3 추천 결과 구조체

검색된 약속 후보의 정보를 저장한다.

| 데이터 | 자료형 | 설명 |
|---|---|---|
| 요일 | 정수형 | 추천 요일 |
| 시작 시간 | 정수형 | 약속 시작 시간 |
| 종료 시간 | 정수형 | 약속 종료 시간 |
| 참석 가능 인원 | 정수형 | 전체 조건을 만족한 참가자 수 |
| 참석률 | 실수형 | 전체 참가자 대비 참석 가능 비율 |
| 평균 선호도 | 실수형 | 참석 가능한 참가자의 평균 선호도 |
| 참가자별 참석 여부 | 문자형 배열 (`char`) | 참석 가능은 `'Y'`, 불가능은 `'N'`으로 저장 |

추천 결과를 별도의 구조체로 관리하면 결과를 정렬하거나 상세 정보를 출력하기 쉽다.

## 5. 사용자 정의 함수 설계

프로그램의 기능을 함수별로 나누어 구성한다.

| 함수 역할 | 처리 내용 |
|---|---|
| 메뉴 출력 | 프로그램의 전체 메뉴 표시 |
| 참가자 등록 | 참가자 정보 추가 |
| 참가자 삭제 | 참가자 정보 제거 |
| 참가자 조회 | 등록된 참가자 목록 출력 |
| 참가자 검색 | 이름을 이용한 참가자 검색 |
| 시간표 입력 | 참가자의 가능 시간과 선호도 입력 |
| 시간표 수정 | 기존 시간표 정보 변경 |
| 시간표 출력 | 참가자의 주간 시간표 표시 |
| 참석 가능 검사 | 특정 참가자가 해당 시간에 참석 가능한지 판단 |
| 공통 시간 검색 | 조건에 맞는 약속 시간 탐색 |
| 선호도 계산 | 약속 후보의 평균 선호도 계산 |
| 추천 결과 정렬 | 참석 인원과 선호도 기준으로 정렬 |
| 추천 결과 출력 | 상위 3개 후보 출력 및 선택한 후보 상세 조회 |
| 입력값 검사 | 잘못된 사용자 입력을 확인 |

구조체 배열은 필요한 함수에 전달하여 데이터를 공유한다. 시간표 수정은 시간표 입력 함수를 재사용한다. 검색 결과는 전역 배열에 저장하고 참가자 등록·삭제 또는 시간표 변경이 성공하면 무효화한다.

## 6. 핵심 알고리즘 설계

### 6.1 공통 시간 탐색 알고리즘

1. 사용자가 약속 소요 시간과 최소 참석 인원을 입력한다.
2. 월요일부터 일요일까지 차례대로 검사한다.
3. 각 요일의 오전 9시부터 가능한 시작 시간을 순서대로 검사한다.
4. 각 참가자가 해당 약속 시간 전체에 참석할 수 있는지 확인한다.
5. 참석 가능한 인원을 계산한다.
6. 최소 참석 인원 이상이면 추천 후보로 등록한다.
7. 모든 요일과 시간대를 검사할 때까지 반복한다.

### 6.2 추천 순위 결정 알고리즘

후보별 참석 인원과 평균 선호도를 계산한 후, 다음 순서로 비교한다.

**1차 비교 — 참석 인원**

더 많은 사람이 참석할 수 있는 후보를 높은 순위에 배치한다.

**2차 비교 — 평균 선호도**

참석 인원이 같다면 평균 선호도가 높은 후보를 우선한다.

**3차 비교 — 요일 및 시간**

두 조건이 모두 같다면 더 이른 요일과 시간대를 우선한다.

정렬이 끝나면 상위 3개 후보를 출력한다.

### 6.3 알고리즘 예시

참가자 4명이 다음과 같이 시간을 입력했다고 가정한다.

| 참가자 | 월요일 14~15시 | 화요일 15~16시 |
|---|---|---|
| A | 가능 (5점) | 가능 (4점) |
| B | 가능 (4점) | 가능 (5점) |
| C | 가능 (5점) | 불가능 |
| D | 불가능 | 가능 (4점) |

각 후보의 결과는 다음과 같다.

| 항목 | 월요일 | 화요일 |
|---|---|---|
| 참석 가능 인원 | 3명 | 3명 |
| 참석률 | 75% | 75% |
| 평균 선호도 | 4.67점 | 4.33점 |
| 추천 순위 | 1위 | 2위 |

두 시간대의 참석 가능 인원은 동일하지만 월요일의 평균 선호도가 더 높으므로 월요일이 1순위가 된다.

## 7. 프로그램 실행 흐름

### 7.1 메인 메뉴 구성

1. 참가자 등록
2. 참가자 목록 조회
3. 참가자 검색
4. 참가자 삭제
5. 가능 시간 및 선호도 입력
6. 시간표 조회 및 수정
7. 공통 가능 시간 검색
8. 최적 약속 시간 추천
9. 추천 결과 상세 조회
0. 프로그램 종료

### 7.2 기본 실행 과정

**1단계 — 참가자 등록**

약속에 참여할 사람들을 등록한다.

**2단계 — 시간표 입력**

각 참가자의 가능 시간과 선호도를 입력한다.

**3단계 — 약속 조건 설정**

약속 소요 시간과 최소 참석 인원을 선택한다.

**4단계 — 자동 탐색**

프로그램이 전체 참가자의 가능 시간을 비교한다.

**5단계 — 추천 결과 생성**

참석 인원, 평균 선호도, 요일 및 시간을 기준으로 후보를 정렬한다.

**6단계 — 결과 확인**

추천 시간 TOP 3와 참석 가능 인원 및 참가자 명단을 출력한다.

## 8. 예외 상황 처리

프로그램의 안정성을 위해 다음 상황을 검사한다.

| 예외 상황 | 처리 방법 |
|---|---|
| 참가자를 등록하지 않은 상태에서 검색 | 참가자 등록 안내 |
| 참가자 수가 8명을 초과 | 추가 등록 제한 |
| 동일한 이름의 참가자 등록 | 중복 등록 안내 |
| 존재하지 않는 참가자 검색 | 검색 실패 안내 |
| 잘못된 요일 또는 시간 입력 | 올바른 입력 범위 안내 |
| 잘못된 선호도 입력 | 1.0~5.0점과 0.1점 단위를 안내하고 메뉴로 복귀 |
| 최소 참석 인원이 전체 인원 초과 | 가능 범위를 안내하고 메뉴로 복귀 |
| 설정하지 않은 시간대 | 참석 불가능으로 처리 |
| 조건을 만족하는 약속 시간이 없음 | 검색 결과 없음 안내 |
| 시간표 변경 후 기존 추천 결과 조회 | 이전 결과를 무효화하고 재검색 안내 |
| 숫자 대신 문자 입력 | 오류를 안내하고 메뉴로 복귀 |

참가자 등록·삭제나 시간표 수정이 성공하면 이전 검색 결과를 사용할 수 없게 하고 다시 검색하도록 한다.

검색 조건을 잘못 입력하면 새 검색을 시작하지 않으므로 이전 검색 결과는 유지된다.

## 9. 테스트 계획

### 테스트 1. 기본 등록
참가자 3명을 등록하고 이름 검색과 목록 출력이 정상적으로 이루어지는지 확인한다.

### 테스트 2. 공통 시간 검색
3명 모두 참석 가능한 시간대를 입력한 뒤 해당 시간이 정상적으로 검색되는지 확인한다.

### 테스트 3. 최소 참석 인원
참가자 5명 중 4명만 참석 가능한 시간대를 설정하고 최소 참석 인원이 4명일 때 검색되는지 확인한다.

### 테스트 4. 연속 시간 검사
오후 2~3시만 가능한 참가자와 오후 2~4시 모두 가능한 참가자를 등록한 뒤 2시간 약속에서 올바르게 구분하는지 확인한다.

### 테스트 5. 추천 순위 검사
참석 인원이 같은 두 후보의 평균 선호도를 다르게 설정하여 선호도가 높은 후보가 우선하는지 확인한다.

### 테스트 6. 결과 없음 처리
최소 참석 조건을 만족하는 시간대가 없을 때 프로그램이 오류 없이 안내 메시지를 출력하는지 확인한다.

### 테스트 7. 데이터 수정
참가자의 가능 시간을 수정하거나 참가자를 삭제한 후 다시 검색했을 때 새로운 정보가 반영되는지 확인한다.

### 테스트 8. 최대 인원 및 잘못된 입력
9번째 참가자 등록, 잘못된 시간 입력, 범위를 벗어난 선호도 입력 등을 시도하여 정상적으로 제한되는지 확인한다.

### 테스트 9. 여러 시간 약속과 경계값
3시간 이상 연속 가능한 시간과 중간에 불가능한 시간이 있는 경우를 비교한다. 1시간과 최대 12시간 약속, 종료 시간이 21시인 후보도 확인한다.
