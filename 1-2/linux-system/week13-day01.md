# 13주차 1차시

## 배운 명령어

### 1. `ip addr`로 네트워크 인터페이스 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `ip addr` |
| 기능 | 네트워크 인터페이스와 할당된 주소를 확인한다. |
| 옵션 | 없음 |
| 인자 | 없음 |

#### 사용 예시

```bash
ip addr
```

`lo`는 자기 자신과 통신하는 루프백 인터페이스다. `inet` 뒤에는 IPv4 주소와 프리픽스 길이가 표시된다. 예를 들어 `192.168.1.10/24`에서 앞 24비트는 네트워크 부분이다. 인터페이스 이름은 시스템마다 다를 수 있다.

---

### 2. `ip route`로 라우팅 테이블 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `ip route` |
| 기능 | 목적지 네트워크별 패킷 전달 경로를 확인한다. |
| 옵션 | 없음 |
| 인자 | 없음 |

#### 사용 예시

```bash
ip route
```

`default via 192.168.1.1 dev eth0`은 더 구체적인 경로가 없는 목적지에 기본 게이트웨이 `192.168.1.1`을 사용한다는 뜻이다. `dev`는 사용할 인터페이스를 나타낸다. 같은 네트워크의 목적지에는 일반적으로 직접 전달하고 다른 네트워크에는 라우터를 거친다.

---

### 3. `hostname`과 `hostnamectl`로 시스템 정보 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `hostname`<br>`hostnamectl` |
| 기능 | 시스템 호스트명과 관련 시스템 정보를 확인한다. |
| 옵션 | 없음 |
| 인자 | 없음 |

#### 사용 예시

```bash
hostname
hostnamectl
```

호스트명은 시스템에 설정된 이름이다. DNS에서 사용하는 도메인명과 같을 수도 있고 다를 수도 있다.

### 4. `nslookup`으로 DNS 조회

| 항목 | 내용 |
| --- | --- |
| 명령어 | `nslookup 도메인명` |
| 기능 | DNS 서버에 질의하여 도메인에 대응하는 IP 주소 등을 조회한다. |
| 옵션 | 없음 |
| 인자 | `도메인명`: 조회할 DNS 이름 |

#### 사용 예시

```bash
nslookup example.com
```

하나의 이름에 여러 IPv4 또는 IPv6 주소가 조회될 수 있다. DNS는 도메인명에 대한 IP 주소 등의 정보를 조회하는 체계다.

### 5. `ping`으로 연결 상태 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `ping -c 횟수 주소` |
| 기능 | ICMP 요청과 응답으로 대상까지의 연결 상태를 확인한다. |
| 옵션 | `-c`: 요청 횟수 지정 |
| 인자 | `주소`: 확인할 IP 주소 또는 호스트 이름 |

#### 사용 예시

```bash
ping -c 2 127.0.0.1
ping -c 4 1.1.1.1
```

`127.0.0.1`은 IPv4 루프백 주소다. 루프백 응답은 자신의 네트워크 기능 확인에 도움이 되지만 외부 인터넷 연결을 보장하지 않는다. 대상이나 방화벽이 ICMP 응답을 차단할 수도 있다.

### 6. `ss`로 수신 대기 포트 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `ss -ltn` |
| 기능 | 수신 대기 중인 TCP 소켓을 확인한다. |
| 옵션 | `-l`: 수신 대기 소켓<br>`-t`: TCP<br>`-n`: 주소와 포트를 숫자로 표시 |
| 인자 | 없음 |

#### 사용 예시

```bash
ss -ltn
ss -ltn | grep ':22'
```

`LISTEN`은 TCP 연결을 기다리는 상태다. IP 주소는 인터페이스를, 포트 번호는 해당 컴퓨터의 통신 접점을 구분한다. SSH는 일반적으로 TCP 22번을 사용하지만 다른 포트로 설정할 수 있다.

### 7. `systemctl`로 서비스 관리

| 항목 | 내용 |
| --- | --- |
| 명령어 | `systemctl status 서비스`<br>`sudo systemctl start 서비스`<br>`sudo systemctl stop 서비스`<br>`sudo systemctl restart 서비스` |
| 기능 | systemd 서비스의 상태를 확인하고 시작·중지·재시작한다. |
| 옵션 | 없음 |
| 인자 | `서비스`: 관리할 서비스 이름 |

#### 사용 예시

```bash
systemctl status ssh
sudo systemctl start ssh
sudo systemctl stop ssh
sudo systemctl restart ssh
```

데몬은 백그라운드에서 실행되어 기능을 제공하는 프로세스다. systemd는 서비스 유닛의 설정을 바탕으로 서비스를 관리하며 `systemctl`은 관리 명령을 전달한다. `restart`는 서비스를 중지한 뒤 다시 시작한다.

### 8. SSH 서버 설치와 접속 확인

| 항목 | 내용 |
| --- | --- |
| 명령어 | `sudo apt install openssh-server`<br>`systemctl status ssh`<br>`ss -ltn` |
| 기능 | SSH 서버를 설치하고 서비스 상태와 수신 포트를 확인한다. |
| 옵션 | `ss -ltn`: 수신 대기 TCP 소켓을 숫자로 표시 |
| 인자 | `openssh-server`: 설치할 패키지 |

#### 사용 예시

```bash
sudo apt install openssh-server
systemctl status ssh
ss -ltn | grep ':22'
```

SSH는 암호화된 원격 로그인과 명령 실행을 제공한다. 서비스가 실행 중인지와 원하는 주소·포트에서 수신 중인지 각각 확인한다.

### 9. `ssh`로 원격 접속과 명령 실행

| 항목 | 내용 |
| --- | --- |
| 명령어 | `ssh 사용자명@서버주소`<br>`ssh 사용자명@서버주소 명령어` |
| 기능 | 원격 셸에 접속하거나 원격 명령을 실행한다. |
| 옵션 | `-p`: 접속할 포트 지정 |
| 인자 | `사용자명@서버주소`: 원격 계정과 서버<br>`명령어`: 원격에서 실행할 명령 |

#### 사용 예시

```bash
ssh student@192.168.1.100
exit
ssh student@192.168.1.100 hostname
ssh -p 2222 student@192.168.1.100
```

명령을 지정하지 않으면 원격 셸에 들어가며 `exit`로 종료한다. 명령을 지정하면 해당 명령을 실행한 뒤 연결을 종료한다. 포트 2222 예시는 서버가 그 포트에서 SSH를 수신하도록 설정된 경우에 사용한다.

### 10. `scp`와 `sftp`로 파일 전송

| 항목 | 내용 |
| --- | --- |
| 명령어 | `scp 원본 대상`<br>`sftp 사용자명@서버주소` |
| 기능 | SSH를 이용해 로컬과 원격 시스템 사이에서 파일을 전송한다. |
| 옵션 | 자료의 예시에서는 사용하지 않음 |
| 인자 | `원본`, `대상`: 전송할 파일과 저장 위치 |

#### 사용 예시

```bash
scp hello.c student@192.168.1.100:~/
scp student@192.168.1.100:~/result.txt .
sftp student@192.168.1.100
```

첫 번째 명령은 로컬 파일을 원격 홈 디렉터리로 보내고, 두 번째 명령은 원격 파일을 현재 디렉터리로 가져온다. SFTP는 SSH 기반의 대화형 파일 전송과 원격 파일 관리를 제공한다.
